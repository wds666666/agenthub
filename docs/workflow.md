# 验证、构建与发布

默认版本号读取 `package.json`，与 `Cargo.toml`、`Cargo.lock` 和 Tauri 配置一致。**用户未指定新版本号时，不改版本号、不自动递增。** 当前版本为 `0.1.3`。

## 什么时候执行什么

| 场景 | 操作 | 创建发行版 |
| --- | --- | --- |
| 仅修改文档、协作规则 | 检查链接与元数据；工作流变化另做语法检查 | 否 |
| 修改程序、依赖、编译脚本 | 格式、静态检查和相关测试 | 否 |
| 用户要求编译、安装包或下载链接 | 手动构建，提供 Actions 临时产物 | 否 |
| 用户明确要求发布 | 从已成功的双平台构建创建发行版，附功能与限制说明 | 是 |
| 用户明确指定新版本号 | 先统一版本元数据，再按其发布要求执行 | 只有明确同意时 |
| 用户明确要求替换同版本发行版 | 重新构建，确认产物后替换该发行版及对应标签 | 是，不递增版本号 |

## 三个工作流

- **检查**（`checks.yml`）：推送与 PR 自动执行。文档改动只运行轻量检查，程序改动才运行前端和 Rust 检查；不生成安装包。
- **构建安装包**（`build.yml`）：手动选择全部、Windows 或 Ubuntu 平台，沿用当前版本。只上传产物，不发布。产物保留 14 天，下载需登录 GitHub，链接写在运行摘要中。
- **发布发行版**（`release.yml`）：只有明确授权后执行。指定成功构建的运行 ID，并显式开启发布；默认标签为当前版本的 `v<版本号>`。检查构建提交、版本、双平台产物和校验值后发布。默认拒绝覆盖现有发行版，明确替换时才开启替换选项。

常用命令：

```bash
# 双平台构建；不改变版本号，也不发布
gh workflow run build.yml --repo wds666666/agenthub --ref main

# 仅 Windows 构建
gh workflow run build.yml --repo wds666666/agenthub --ref main -f platform=windows

# 仅在用户明确同意本次发布后执行
gh workflow run release.yml --repo wds666666/agenthub --ref main \
   -f build_run_id=<成功运行ID> -f approved=true
```

发布使用所选提交的 `docs/releases/v<版本号>.md`，简要列出已实现与未完成内容。构建、推送或历史发布的授权不能代替本次发布授权。替换既有发行版时，需额外指定 `replace_existing=true`，只处理当前版本。
