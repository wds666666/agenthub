# AgentHub UX contract

- Chinese is the default locale. Every visible string is resolved from an i18n key; English has the same key structure.
- Initialization follows scan → select imports → validate staged Canonical → finish. Nothing is written to a host during initialization. Results are grouped into Skills, MCP, Plugins and Rules with independent counts and selection controls; source host and full resource name remain visible, and duplicate-looking resources are distinguishable by source and path. Discovered resources that are empty, unreadable, unsupported, oversized, or otherwise invalid remain visible with a reason but cannot be selected; “select all” includes only importable resources. A failed validation leaves initialization incomplete and preserves an empty Canonical destination. Legacy invalid initialization data may be reset from the fatal state only when Canonical has no commit, after explicit confirmation; this removes imported AgentHub copies but never edits a host.
- Inventory edits validate before save, remain in the Git working tree and show a persistent “待提交” state.
- Inventory supports cross-category selection, selecting visible search results or a visible category, and clearing selection. Search changes preserve selections. Bulk deletion confirms the exact names and total, validates the entire batch before moving anything, archives removed Canonical directories in a private local backup, and runs saved automatic-sync profiles once after the batch. Failure before completion restores staged resources. The backup location remains visible after success; deletion remains uncommitted until the user saves a version.
- Import always shows Shared Agents, Cursor, Codex and Claude Code, including zero-result sources. Counts distinguish scanned resources from selectable new resources. An empty source explains the global-only scan and protected plugin-cache limitation; no source tab disappears merely because it has no new content.
- Every inventory row is keyboard- and pointer-accessible and opens a read-only Canonical detail. Skills preview `SKILL.md`; MCP previews `server.json`; Rules preview their Markdown and retain a separate edit action; Plugins preview the AgentHub manifest plus a safe file inventory rather than executing or rendering payloads. Detail read failures preserve the inventory and expose retryable inline feedback.
- Inventory offers an explicit destructive delete action for each Canonical capability. The confirmation names the capability, explains that enabled automatic-sync targets may update selected capabilities; Preserve mode retains retired host copies, and never presents deletion as direct unmanaged host editing. After deletion, saved automatic-sync profiles run through the normal Plan → backup → Apply → verify transaction path.
- Post-initialization capability import is user-initiated and never scans automatically. In v0.1 the desktop import/editor first supports Rules: choosing a Markdown file initializes a reviewable draft, and no Canonical file is written until the user explicitly saves it.
- Rule create and edit use the same maintained form. “Rule ID” means the stable unique lowercase slug used for the Canonical directory, adapter references, and history identity; the UI explains this with an example. Save validates the lowercase slug ID, non-empty body, activation metadata, paths, and at least one compatible target; failures preserve the complete draft. Editing keeps the existing ID immutable in v0.1.
- Search is local, IME-safe, debounced when work is non-trivial, and has an owned clear control.
- Sync supports a reviewed one-off path and a persisted automatic path after choosing target and scope. “Preview Plan” follows generate → review exact named capability additions/replacements/deletions, capability-level impact, raw file changes and warnings → explicit confirmation → Apply → verify. “Enable automatic sync” first shows and reconciles the current named scope, then stores the target and selection in SQLite only after that reconciliation succeeds. Subsequent Canonical mutations made through AgentHub invoke the same deterministic Plan, backup, Apply and verification pipeline for every enabled target. Plan generation has no host side effects. The primary summary groups affected Skills, MCP servers, Plugins, and Rules and separates create, update/replace, delete, and skipped counts; raw file count and paths remain available as implementation detail.
- Automatic sync is mutation-triggered, not a filesystem watcher or host scanner. It never imports or merges host-side edits. A run with zero file changes creates no persisted Plan, backup, or transaction. Any host mutation always creates a full rollback-capable transaction and records `mode=auto_sync`. Consecutive successful automatic-sync transactions may be collapsed by target and local date in the history UI, but every underlying transaction and rollback action remains individually accessible. A failure on one target does not block other enabled targets or undo the Canonical edit; the UI reports the failed target and leaves drift visible for retry.
- Compatibility loss or plaintext secret materialization requires a separate acknowledgement from the ordinary Apply confirmation.
- Loading preserves layout. Empty, error, stale and partial states retain the last trustworthy data and expose retry where safe.
- Desktop failures include a stable diagnostics location. Release builds write redacted logs under the operating system application log directory; Windows GUI launches never depend on a console window. Settings shows the resolved log directory and Git availability so support requests can include the log without exposing MCP secrets.
- Page changes and pointer feedback remain immediate while Git, scan, Plan, Apply, rollback and history I/O are running. Those operations execute outside the WebView event thread. Windows external processes are created without a console window; adding the GUI subsystem attribute only to the desktop entry point does not satisfy this contract.
- Target Sync has one reliable page scroll owner. Nested capability lists hand wheel/touch scrolling back to the page at their boundaries, and modal scroll locking is reference-counted so closing overlapping dialogs can never leave the app frozen.
- `Shared Agents` is visibly Skills-only. Clearing it is an explicit managed-empty action with deletion preview, backup and rollback; an empty checkbox list alone never ambiguously means both "ignore" and "delete".
- Inventory provides an explicit post-initialization `Scan and import` flow. Results are grouped by capability type and source, exact duplicates are labeled and disabled, and importing requires review.
- A separate **Host Resources** destination sits between Canonical Inventory and Target Sync. It shows Shared Agents, Cursor, Codex and Claude Code through target tabs, groups rows by Skills, MCP, Plugins and Rules, and labels each row as a Canonical match, host-only resource, or protected host constraint. The relationship label is descriptive and must not claim filesystem ownership.
- Host cleanup is selection-based and limited to adapter-confirmed writable resources. Protected vendor/CLI/organization stores remain visible with a disabled control and reason. A sticky action bar names the selected count; confirmation lists exact resources and warns that deleting a Canonical match creates drift and may be recreated by automatic sync. Cleanup preserves Canonical and reports its local backup path. A page-level “select resources not in AgentHub” shortcut may pre-select every `host_only` + deletable row of the current target; it never selects Canonical matches or protected constraints, never deletes by itself, and the confirmation requires an explicit acknowledgement checkbox after listing each resource before the destructive action is enabled.
- Settings chooses Preserve or Replace as the default for new scopes. Saved automatic profiles retain their confirmed mode and IDs. Neither mode expands scope; vendor, organization, cloud and undocumented storage remain protected.
- Settings separately controls whether a manual reverse import runs saved automatic-sync profiles. The safe default imports only into Canonical and leaves every host untouched.
- Failures preserve user input. Successful mutations show an app-owned toast and move focus to a useful status heading.
- Saving a version requires a user message and is available from the Versions page. When Git identity is missing, the same form requests name and email and writes them only to the AgentHub repository-local configuration. Restore is blocked when the tree is dirty by default and writes historical content as new working-tree changes, never `reset --hard`.
- Rollback shows exactly which transaction and target will be restored and explicitly states that it restores the host state captured immediately before that Apply. It does not modify Canonical. A manual rollback first backs up the current writable domains, verifies the restored backup, records a new rollback transaction, and leaves detectable drift for a later Plan. Backup cleanup states that future rollback will become impossible.
- Dialogs trap focus, close on Escape unless an operation is irreversible/in progress, and restore focus to the trigger. No browser alert, confirm or prompt is permitted.
- User-facing Chinese copy prefers plain product terms over internal architecture vocabulary: the Canonical source is “AgentHub 库”, Git commits are “版本”, Plans are “变更预览”, transactions are “同步记录”, hosts are “工具”. English mirrors this (library, versions, change preview, sync history, tools). Internal identifiers, schemas and docs keep the original terms.
- Destructive action labels name the consequence, such as “覆盖 Cursor” or “删除备份”, not generic “确定”.

- Settings exposes Reset AgentHub with typed AGENTHUB confirmation. It lists library, versions, settings, credentials and local synchronization records being removed from the active root, explains the private recovery copy, and returns to the scan/import wizard on success.
- Versions exposes remote repository and branch, Connect, Disconnect and Sync now. Connecting tests read access without pushing. Saving a version distinguishes local success from remote failure; a persistent retryable error explains conflicts and authentication. HTTPS sign-in accepts repository-scoped access tokens in the desktop; existing system Git credentials and SSH remain supported. Author identity stays separate from sign-in. Remote synchronization does not automatically modify tool resources.
- Both initialization and later Scan and import reuse a source filter above capability categories. Sources retain independent selection counts; switching source/kind never clears selected IDs. Group-selection acts only on the visible source/category; a separate source action selects all importable resources from that source. The summary always shows total selections and unique resource count, explaining deduplication before import.
- Skill import lists only first-level skill directories; nested skills remain part of the parent resource. Import row checkboxes stay keyboard-accessible and positioned within their own row so focusing them scrolls the list without adding invisible overflow to its ancestors. Repeated selection and source/category switches preserve the visible interface. Initialization fits its panel within the viewport insets; only genuinely overflowing content scrolls. Pending import blocks repeated submission and selection changes, and failure preserves the selection for retry.
- Skill rows explain excluded local environments/caches while remaining selectable. Unsafe or invalid retained content is shown with a localized reason and diagnostic path, and cannot be selected. Import failures show the underlying cause as well as the source resource; selection remains available for correction/retry.

## Git sign-in

First run offers two equally discoverable actions: create a library from local tools, or restore an existing AgentHub library. Restore reuses repository fields, shared credential fields, Button, inline error/status and token controls from Versions. Branch is optional with an explicit auto-selection hint. HTTPS supports token or system credentials; SSH uses the existing system agent. Pending blocks repeated submission and switching paths. Errors preserve the form and explain retry, unsupported layouts and existing-data protection. Back clears sensitive input. Success opens the library with a restored-resource toast; no tool is changed. New-library import also offers an explicit empty-library action instead of requiring a scan.

Versions offers a repository sign-in dialog for GitHub and self-hosted Git/Gitea. It shows the repository address, username, a hidden access token with an accessible reveal button, local encrypted persistence and required repository read/write permissions. Loading, failure and success are visible inline. Submission blocks closing and repeat submission. Failed validation preserves form input; closing clears the token. Sign-in and sign-in-and-retry have distinct labels. Read access does not imply upload permission.

## Skill change reminders

Initialized desktop entry and visible-window checks detect different portable content for existing Skill IDs across all four tool roots. Navigation and affected library rows show a red dot with a localized accessible label; the library also shows a count and review action. Opening a reminder preserves it until content is imported or restored to a known library digest. Review reuses the source/category import dialog, starts with no selection and explains that importing preserves the original and adds a separate entry. Checking/error states remain inline; a partial error retains valid results and does not claim all Skills are unchanged. Hidden windows do not periodically check; returning to the window respects the same two-minute cooldown.

## Selected capability synchronization (current contract)

Preserve is the default: add/replace only explicitly selected capabilities; leave every unselected host resource intact, including retired selections and library deletions. Replace reconciles only explicitly managed categories to the selected subset. Neither mode expands scope. Rules have individual IDs; creating a rule saves only to Canonical and never distributes it or selects it. Existing selected rules may synchronize on subsequent edits. Old automatic profiles pause for mode/rule-scope review. Package installation supplies Desktop and CLI, with the manager Skill available separately for manual installation.

Discovery uses a shared comparison digest of portable capability content, separate from transaction file digests. MCP compares normalized target-representable configuration, Rules exclude generated wrappers, Plugins compare their complete payload, and Skills retain runtime exclusions. Generated rule containers are identified explicitly. Equal content is blocked from reverse import in the backend as well as the UI; same-name differences remain reviewable. Parsing/identity uncertainty blocks destructive rewriting rather than treating the configuration as empty.

The synchronization mode picker reuses native radio semantics with text consequences. Saved profiles requiring upgrade review display an inline warning; mode changes invalidate the visible Plan. Settings controls the default for new scopes only. Rules use the same per-capability picker as Skills and MCP.

Versions exposes Refresh, Discard unsaved changes, and Use remote content as distinct actions. Capability names/categories/actions/counts precede raw file details. Destructive dialogs list the exact affected capabilities and candidate version; confirmation requires typing DISCARD or REMOTE. Pending requests disable double submission and dismissal, failed requests retain the preview, and success reports the private recovery path. Remote replacement retains local version history and requires a later explicit save; neither recovery action writes tools.
